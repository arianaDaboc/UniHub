Academic workspace platform

One system for courses,
deadlines and academic work.

UniHub is a full-stack web application that centralises information normally scattered across learning platforms, email, PDF files and messaging groups. It provides separate, authorised workflows for students, professors and administrators.

Project objective. Demonstrate production-oriented full-stack fundamentals: relational modelling, REST API design, JWT authentication, role-based authorisation, file handling, scheduling, database migrations and a typed React user interface.

UniHubArchitecture and Technologies

Technology stack and request lifecycle

Frontend
React 18 + TypeScript 5 + Vite 6. Component state, typed API contracts, responsive layouts and Lucide icons. The browser stores the signed session token and sends it in the Authorization header.
API
Java 17 + Spring Boot 3.3. Spring MVC exposes REST endpoints; Jakarta Validation rejects malformed requests before business logic runs.
Security
Spring Security + JWT + BCrypt. Stateless authentication, role authorities, token expiry and endpoint/service ownership checks.
Persistence
PostgreSQL + Spring Data JPA + Hibernate. Entity relationships map to explicit foreign keys and uniqueness constraints.
Delivery
Flyway + Maven + JUnit 5 + Mockito + H2. Repeatable schema evolution and automated backend verification.
Email
Spring Mail + scheduled jobs + Mailpit. Deadline messages are captured in a local inbox without external email accounts or credentials.

Authenticated GET request

1

React calls the API. The typed wrapper builds a URL such as /api/courses and attaches Authorization: Bearer <JWT>.

2

JwtAuthenticationFilter validates identity. It extracts the email subject, loads current authorities and populates Spring's security context.

3

The controller maps HTTP to an application operation. DTOs define input/output boundaries; JPA entities are not exposed directly.

4

The service executes rules. It verifies role, course ownership, enrolment, capacity, prerequisites or review eligibility as required.

5

The repository issues SQL. Hibernate maps records to entities inside a transaction and the response is serialised as JSON.

6

React updates state. Loading, success, empty and error states are rendered without a full page reload.

Security behaviour

401 UNAUTHORISED

Missing or expired token. The frontend clears the stale session and returns to sign-in.

403 FORBIDDEN

Identity is valid, but the role or ownership rule does not permit the requested action.

UniHubStudent Experience

Student role

Discovery, planning, progress and academic resources

Account and course discovery

  • Registration accepts university-provided addresses while blocking common personal providers.
  • The catalogue supports live search by course, professor or department, plus department filters and sorting.
  • Enrolment checks capacity, duplicate membership and required prerequisite courses.
  • Course detail exposes professor, ECTS, schedule, materials, assignments and reviews.

Daily academic workflow

  • The dashboard aggregates enrolled courses and upcoming deadlines.
  • Students mark assignments complete or undo completion.
  • Progress is calculated as completed assignments divided by total assignments for each course.
  • The weekly schedule displays only courses in which the student is enrolled.

Materials, calendar and communication

Materials

Authenticated PDF download preserves the original filename while files are stored under generated safe names.

Calendar

Assignments are exported as an .ics file that can be imported into Outlook, Google Calendar or another calendar application.

Notifications

New assignments, course materials and approaching deadlines create deduplicated in-app updates.

Reviews and recommendations

Reviews require an eligible enrolment period and are unique per student/course. Recommendations use a SQL co-enrolment query: courses frequently taken by students with similar enrolments are ranked without introducing unnecessary machine learning infrastructure.

Student boundary: students cannot create courses, upload materials, publish schedules, create assignments, inspect another course's student list or change account roles.

P

Professor workspace

  • Create a course with name, description, faculty, department, ECTS credits and capacity.
  • View only owned courses in the professor workspace, including total enrolment and published schedule metrics.
  • Publish assignments through the course interface with title, description, European date/time and maximum points. The assignment appears immediately and enrolled students receive an internal notification.
  • Upload validated PDF materials, define prerequisite courses and publish weekday/time/room schedule entries.
  • Inspect the enrolled-student list and send a Mailpit test notification only to students enrolled in the owned course.

Administrator workspace

  • List user accounts and promote authorised users between Student, Professor and Administrator roles.
  • Create and manage courses across the full catalogue, independent of professor ownership.
  • Create assignments, schedules, prerequisites and course resources for any course.
  • Delete courses while database constraints remove dependent resources safely.

Deployment model

Browser client

Static React assets communicate with the API through a typed request layer and role-aware interface.

Application service

The Spring Boot process remains stateless and keeps business rules inside dedicated services.

Local services

PostgreSQL provides durable relational data while Mailpit captures scheduled academic reminders.

Evolution path. CI can run the existing Maven and TypeScript checks before deployment. Containerisation and object storage remain optional infrastructure improvements that do not require changes to the core course, enrolment or assignment model.
